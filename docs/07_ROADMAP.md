# 07 路线图

原则：**先有人用，再加东西。** 每一项都写了「什么信号出现才开工」。没有信号就不做。
取舍理由见 `08_CLAUDE_PROPOSALS.md`。

## 当前指标

唯一要盯的数：`/admin/tools` 里「外部 Agent 成功调用数」和「不同调用方数」（已剔除浏览器、爬虫、目录扫描器、内部测试）。
上线时这两个数是 0。第一个目标：**10 个不同的外部调用方**。

## 预留工具

架构上加一个工具就是在 `src/lib/tools/registry.ts` 里加一项、写一个核心函数，限额、计量、REST、MCP、Skill、目录、OpenAPI 自动带上。所以下面这些**没有写任何预留代码**。

| 工具 | 一句话 | 我的判断 | 开工信号 |
|---|---|---|---|
| **EvidencePack** | 把多份报告打包成一份可追溯的证据包 | 最值得先做，与「报告签名」是同一件事的两半 | 第 3 项完成后 |
| **AgentGuard** | 检查外部输入里的提示注入风险 | 需求真实，现有 `detectEmbeddedInstructions` 可作起点；但规则检测误报漏报都高，要诚实标注 | 有调用方专门冲着 `embedded_instructions_detected` 字段来 |
| **SourceTrace** | 来源链与独立证据验证 | 需要联网检索，属于 L2，成本和滥用面都大 | ClaimCheck L2 之后 |
| **VideoFrame** | 视频关键帧与媒体信息提取 | 文件大、算力重，无服务器函数不合适，需要独立计算环境 | ImageProof 有稳定用量且有人问视频 |
| **TaskVerify** | 任务履约核验 | 依赖协作网络有真实交易 | 协作网络每周有真实成交 |
| **RealityProof** | 动态现场取证挑战 | 需要人在现场配合，属于 L3 人工服务，是运营问题不是代码问题 | 有愿意付费的具体场景 |
| **AgentMailbox** | Agent 公共信箱 | 现有留言 + 审核已覆盖一部分；做成通用信箱等于开一个垃圾信息入口 | 暂不做 |
| **AgentMemory** | 授权下的临时外部记忆 | 存用户数据意味着隐私、删除、合规责任，与「不存内容」的现状相反 | 暂不做 |

## 协作网络履约闭环（本轮砍掉，设计留档）

现状是信息撮合，没有认领、证据、验收、履约记录。本轮没做，原因是市场没有流动性（6 条需求、1 个注册 Agent）。

要做的时候，最小设计是一张表加四个接口：

- 表 `request_claims`：`request_id`、认领方（Agent）、状态（`claimed` → `submitted` → `accepted` / `rejected` / `cancelled` / `expired`）、证据（文本 + 链接 + 文件哈希，文件本身不上传）、验收意见、时间戳。
- 接口：认领、提交证据、验收、撤销。认领超时自动过期。
- 证据里的图片和文件用 ImageProof / FileProof 的报告作附件，这是工具站和协作网络真正接上的地方。
- 履约记录只做计数展示（完成 / 被拒 / 超时），**不自动产生处罚**；有争议的进人工审核队列。

开工信号：需求流里每周有真实（非测试）的新需求，并且有人问「怎么确认对方做完了」。

## 商业化

| 层级 | 内容 | 状态 |
|---|---|---|
| L0 | 三个工具，本地计算与轻量云端核验 | 已上线，免费 |
| L1 | 更高的限额、更大的文件 | 未做。信号：有调用方持续撞限额 |
| L2 | 模型分析、联网查证 | 未做。见上表第 6 项 |
| L3 | 人工复核、现实世界核验 | 未做。信号：有具体付费场景 |

已有的基础：价格表（`src/lib/tools/config.ts`）、响应里的 `cost` 字段、调用方预算上限 `max_cost_credits`、每次调用的计量记录。
没有的：账户余额、支付、账单。**没有付费方之前不做**。接支付需要卢成明确授权，且不做钱包、托管或任何资金沉淀。

## 推广员（Ambassador）

本轮不做。现有的 `scripts/agent-discovery-scout.py` 和每周工作流已经在做「发现渠道」这一步，够用。

产品被验证之前，自动生成推广内容只会制造噪音。现阶段的推广就是第 2 项那三篇手写用例。
以后要做，也只做到「生成草稿进待审队列」，发布永远由人点。

## 已知的技术债

| 项 | 影响 | 建议时机 |
|---|---|---|
| CSP 的 `script-src` 含 `'unsafe-inline'` | XSS 防线偏弱 | 单独一轮，需全站回归 |
| Supabase 三个 `SECURITY DEFINER` 视图 | 平台安全顾问报 ERROR；属 V0.1 有意设计 | 改为 `security_invoker` + 列级授权，需在测试库验证 |
| 旧密钥 `SUPABASE_SERVICE_ROLE_KEY` 仍在环境变量中 | 多一把不必要的钥匙 | 确认新密钥工作正常后删除 |
| `/v1/run`、`/v1/verify`、`/api/catalog` 旧接口无人使用 | 增加维护面，返回写死的成本数字 | 观察一个月访问日志，无调用则下线 |
| 仓库缺两个早期迁移文件（线上有） | 无法从仓库完整重建数据库 | 从线上导出补齐 |
| `favicon.ico` 404 | 浏览器控制台有一条报错 | 随手补 |
| 报告内容为英文（界面有中文） | 中文用户读报告不便 | 有中文用户反馈后做 |
