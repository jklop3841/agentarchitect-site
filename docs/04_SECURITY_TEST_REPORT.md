## 3. 分项说明

### 3.1 SSRF 与私网访问

防护做法（`src/lib/tools/safe-fetch.ts`）：

- 只允许 `http` / `https`，只允许 80 / 443 端口，URL 里不许带账号密码。
- 主机名只解析一次。解析出的**每一个**地址都必须是公网地址，然后直接连那个地址，不再二次解析。DNS 重绑定没有可钻的时间差。
- 重定向不自动跟随，每一跳重新走完整校验，最多 3 跳。
- 响应体流式读取，超过上限立即断开；整体有截止时间；拒绝压缩响应（防解压炸弹）。
- 不带 Cookie、不带认证头。
- IPv6 只放行全球单播段（`2000::/3`）并扣除保留段，其余一律拒绝，不靠逐个列举。
- 整个调用（含 DNS 解析）受同一个截止时间约束；连接提前关闭、协议切换应答都会以错误结束，不会挂起。
- 运营方可用 `TOOLS_FETCH_DENY_HOSTS` 追加禁止的主机后缀。

测试覆盖（`tests/tools-safe-fetch.test.ts` 15 项，`tests/tools-api.test.ts` 的 SSRF 组）：

| 类别 | 用例 |
|---|---|
| 地址段 | 回环、三个私网段、链路本地（含云元数据地址）、运营商级 NAT、组播、保留段；IPv6 的回环、唯一本地、链路本地、IPv4 映射、NAT64、6to4、Teredo。共 30 个地址全部判为非公网，8 个正常公网地址判为公网 |
| IP 的各种写法 | 十进制整数、十六进制、八进制、省略写法、带方括号的 IPv6、IPv4 映射的两种写法 |
| 主机名 | `localhost`、单标签名、`.internal`、`.local`、`.corp`、云厂商元数据主机名 |
| 协议 | `file:`、`ftp:`、`gopher:`、`javascript:`、`data:` |
| DNS | 解析结果里混有一个私网地址即拒绝 |
| 重定向 | 跳到元数据地址、跳到 `localhost`、跳到 `file:`、无限循环 |
| 资源 | 声明超大、不声明但流式超大、服务器不响应（超时）、压缩响应、非 200 |

自测中发现并修掉的缺陷：最初把 IPv4 映射段写进了 Node 的 `BlockList`，结果所有公网 IPv4 都被拦。
独立复核又找出四处：收到 101 应答会永久挂起、截止时间不含 DNS、畸形重定向地址变成 500、个别 IPv6 段漏判。均已修复（第 5 节）。

### 3.2 文件不会被执行

工具对文件只做三件事：读字节、算哈希、按格式规范解析头部。没有任何代码路径会执行、解释或渲染收到的文件。

- 类型识别只比对文件头的固定字节，不依赖文件名。
- 文件不落盘，只在内存里处理，请求结束即释放。
- ImageProof 只接受七种位图格式。SVG（可带脚本）、改名成 `.jpg` 的可执行文件都会被拒。
- 网页端不显示图片预览（也就不会渲染不可信图片）。
- 测试：提交一个改名为 `photo.jpg` 的 shell 脚本，脚本要创建的标记文件事后不存在；截断的、全是垃圾字节的图片不会让解析器崩溃或卡死。
- 元数据读取不用任何通用解析库（复核后改）。EXIF 用自写读取器（`src/lib/tools/exif.ts`），只读约二十个字段，每个循环都有与文件内容无关的上限，单个值最多读 1 KB；XMP 只在最多 256 KB 内用定长模式取五个字段。IPTC 只报告是否存在。

### 3.3 不可信内容

工具核心是纯函数：不调用模型，不持有凭据，不能发起除「用户指定的那一次受限抓取」之外的任何动作。所以被检内容里写什么指令，都没有东西可以被它指挥。

在此之上：

- 来自文件、文本的字符串进入报告前去掉控制字符、ANSI 转义和双向文本覆盖字符，并截断长度。
- 每个响应都带 `untrusted_content_notice`，提醒调用方的 Agent 不要执行报告里引用的内容。
- 发现疑似指令的文本时给出提示（ImageProof 的 `embedded_instruction_text`，ClaimCheck 的 `embedded_instructions_detected`）。
- 请求体严格校验，多余字段直接拒绝。

测试：在 ClaimCheck 输入、图片元数据、文件名里放注入文本（要求改计费、改状态、把所有主张判为支持、输出环境变量），断言响应的 `tool`、`status`、`cost`、各主张结论均不变，响应里不出现任何环境变量名。

要说清楚的一点：指令检测是启发式的，会漏。**真正的防线是工具本身没有权限**，不是检测。

### 3.4 成本约束

| 机制 | 默认值 | 作用 |
|---|---|---|
| 单实例突发限制 | 每调用方 30 次/分钟 | 第一道，内存计数 |
| 每调用方小时限额 | 调用 120 次，URL 抓取 20 次 | 数据库计数，跨实例生效 |
| 全站每日上限 | 调用 20,000 次，URL 抓取 1,000 次 | 熔断：到顶后该模式对所有人停用到次日 |
| 输入上限 | 请求体 4.4 MB，内联文件 3 MB，远程文件 8 MB，文本 2 万字符 | 限制单次调用的计算量 |
| 远程抓取 | 6 秒截止，最多 3 次跳转 | 限制带宽和挂起 |
| 总开关 | `TOOLS_REMOTE_FETCH=off` | 一键关闭对外抓取 |

计数顺序：先查单个调用方的限额，通过了才计入全站上限。被自身限额拒绝的调用不消耗全站额度，否则一个调用方狂刷就能让所有人当天用不了（这是复核发现后改的）。

数据库不可用时自动退回内存计数，不会因为数据库故障变成不限量。
测试覆盖：小时限额、全站熔断、无数据库时的突发限制、URL 抓取独立限额、总开关、预算上限（把某个模式临时标价后验证 `budget_exceeded`）。

三个工具都不调用付费的外部服务，单次调用的边际成本就是函数执行时间和抓取流量。

### 3.5 隐私与数据

- 被检的文件、文本、URL、哈希**都不存储**。
- 用量记录只有：工具名、渠道、输入方式、成功与否、错误码、来源分类、字节数、耗时、加盐哈希后的 IP、截断的 User-Agent。
- 数据库层面有约束：`ip_hash` 字段只接受 64 位十六进制，原始 IP 写不进去。
- 新表开启 RLS，没有任何策略，匿名和登录用户都没有权限；只有服务端密钥能读写。PGlite 校验覆盖了匿名读、匿名写、匿名调用清理函数均被拒。
- 保留期 90 天，由 `aa_purge_tool_usage()` 清理（需定期调用，见 `06` 第 5 节）。
- 测试断言：一段含「机密」字样的输入文本不会出现在用量记录里。

### 3.6 C2PA 库

官方库默认会联网：按图片里写的地址去拉远程清单，按证书里写的地址去查吊销状态。这等于让一张图片指定服务器去请求哪个地址，是一条绕过 3.1 节全部防护的 SSRF 通道。

**初稿在这里犯了错。** 当时调用了库提供的设置函数把两个联网开关关掉，并在文档里写了「已禁止」。实际上那个函数返回的是驼峰命名的对象，原生层只认下划线命名的 JSON，于是设置被整个忽略，联网一直开着。独立复核用一张带远程清单地址的图片复现了对外请求。

现在的做法：

- 设置一律经库的 `settingsToJson()` 转成原生格式再传入。
- 传入前检查生成的 JSON 里两个开关确实是 `false`，不是就直接抛错、不做校验（宁可不校验，也不带着联网能力跑）。
- 信任锚只接受环境变量里的内联 PEM，配成 URL 会被忽略。
- 图片指向远程清单时，如实报告「未抓取」，不回显那个地址。

验证：测试里起一个本地监听端口，把它的地址写进图片，分别直接调用校验函数和走公开接口，断言端口收到 0 次请求。冒烟脚本里也有一项对应检查。
修复后信任锚同样开始生效：配置测试用中间证书后，有效样本得到「受信任」，被篡改样本仍是「无效」。

代价：不检查证书是否已被吊销；存放在远程的内容凭证不校验。两点都写进了工具的 `limitations`。

**其他可能的联网途径（第三轮专门测试）。** 用 `scripts/c2pa-network-probe/probe.mjs`：运行时自建一次性 CA、签名证书和 RFC 3161 时间戳服务，签出下列样本；校验时把 `HTTP_PROXY` 等变量指向一个本地观察代理，任何主机、任何端口的请求都会被看到。先做校准：SDK 默认设置下去抓远程清单，观察代理确实捕获到了（证明观察手段有效）。

| 样本 | 网站设置 | SDK 默认设置 | 开启远程抓取和 OCSP |
|---|---|---|---|
| XMP 里写远程清单地址（校准） | 0 次 | 1 次 | 1 次 |
| 签名证书带 OCSP、颁发者证书、吊销列表地址 | 0 次 | 0 次 | 1 次（仅 OCSP） |
| 内嵌清单旁另附远程地址 | 0 次 | 0 次 | 1 次（仅 OCSP） |
| 成分（ingredient）的清单在远程 | 0 次 | 0 次 | 1 次（仅 OCSP） |
| 带时间戳（时间戳证书也带上述地址） | 0 次 | 0 次 | 1 次（仅 OCSP） |

时间戳服务只在签名时被访问 1 次，校验时从未访问；颁发者证书和吊销列表地址在任何设置下都没有被访问。

局限：观察手段依赖 SDK 遵循代理环境变量（校准证明它遵循，但只能证明走 HTTP 客户端的那条路径）；CAWG 身份断言里的 `did:web` 解析没有构造出来测试。升级 SDK 后必须重跑这个脚本，脚本失败会返回非零退出码。

### 3.7 结论措辞

这类工具最大的风险不是被攻破，而是说了过头的话。自动化测试里固定了以下几条：

- 没有元数据的图片结论是「无法判断」，对应说明里必须出现「不是造假的证据」。
- 任何输出里不出现概率、分数、置信度字段，也不出现百分比。
- 没有配置信任列表时，三张样本没有一张得到「已验证来源」。
- 即使凭证受信任，只要与调用方的陈述冲突，结论仍是「发现矛盾」。
- ClaimCheck 的「支持」只在一句证据与主张的数字完全一致时给出（见下）。

最后一条出过三轮问题，前两轮都是逐条修补：自测发现一个数字对上就判「支持」；第一轮复核又发现截断、负号、中文数字、单位、互换；第二轮复核又发现全角数字、模糊数、限定词、证据后文更正。第三轮复核构造了 27 个误导样本，其中 19 个仍被判「支持」（证据里多出数字、未知单位被当作任意单位、涨跌方向、`<`/`~`/`+` 等符号、其他文字的数字、序数、分数、货币代码等）。

逐条修补显然没有尽头，所以第三轮改了思路，把「支持」的门槛整体收到保守一侧。现在要判「支持」，必须同时满足：

- 有一句证据，和主张的数字**完全一致**：不多也不少，单位、限定词、正负号都相同，同类数字的顺序也相同。
- 涨跌方向一致。
- 两边都没有本模块读不懂的数字。
- 这份证据里没有更正类字样。

达不到就是「无法定论」；涨跌方向相反或单位不同则判「反驳」。代价是部分本该判「支持」的会落到「无法定论」，对一个规则版的 beta 工具，这是正确的方向。

## 5. 独立复核

自测完成后，请另一个 Agent 做了一次只读复核。它没有看我的结论，只拿到代码和「找问题」的任务，可以自己写探测脚本。它的结论是 **不通过**：当时 178 项测试全过，但没有一项能发现下面这些问题。

### 5.1 发现与处理

| # | 级别 | 问题 | 复现方式 | 处理 |
|---|---|---|---|---|
| 1 | 阻断 | C2PA 库的联网开关没有生效，图片可以让服务器向任意地址发请求（盲 SSRF） | 在图片 XMP 里写一个远程清单地址，本地监听端口收到了请求 | 已修。见 3.6 |

### 5.2 这件事说明什么

1. **自测通过不等于安全。** 第 1 条的错在于我验证了「调用了关闭联网的函数」，没有验证「联网确实关了」。对安全开关，只有观察不到副作用才算数。
2. **写在文档里的安全声明必须有对应的测试。** 现在每条都有：不联网有本地监听端口的测试，不爆内存有计时和内存断言。
3. 复核的成本远低于这两个问题上线后的代价。以后安全相关的改动应当固定走一次独立复核。

### 5.3 修复后的验证

#### 第二轮复核（复审）

修复后请同一个复核 Agent 复审，并专门尝试攻破新代码。结论仍是 **不通过**，但原因变了：

- 原 10 条：9 条确认修复（第 2 条「已修但扫描可绕过」，第 6 条「部分修复」），第 10 条按设计未改。
- **新的阻断级问题**：一个 40 字节的 HEIC 或 AVIF 文件（一个零长度的盒子）让元数据库 `exifr` 进入死循环，进程卡死、计时器也不再触发。这在第一轮就存在，第一轮没发现。
- 第 2 条的修复可被绕过：把第一个目录项的类型写成 0，预算检查就会跳过这个目录（标签白名单仍把损害压在约 1 秒、110 MB）。
- 第 2 条的修复引入了误判：一个正常的 6 MB 分层 TIFF 被说成「畸形」，元数据不读。
- 第 6 条仍有漏判：全角数字（`５亿` 对 `９亿`）、`十几万` 对 `几十万`、`a dozen` 对 `a hundred`、`over 500` 对 `under 500`、证据里先写对后更正。
- C2PA 联网的其他途径：OCSP 已确认关闭；CAWG 身份里的 `did:web` 解析未能复现对外请求；成分（ingredient）里的远程地址、时间戳服务在校验时是否联网，**未测试**。

处理：

- **`exifr` 整体移除。** 两个阻断级问题都出在这一个第三方库上，继续打补丁不划算。本服务只需要约二十个字段，改为自写读取器 `src/lib/tools/exif.ts`：每个循环都有与文件内容无关的上限，单个值最多读 1 KB，不分配大块内存。在三张真实样本和构造样本上与原库逐字段对比，结果一致。
- 因为读取器本身不会被拖垮，之前的「解析前预算检查」不再需要，已删除。这同时消除了绕过问题和对正常大 TIFF 的误判。
- ClaimCheck：全角数字先归一化；带「几」的模糊数和 `dozens of` 一类范围不判「支持」；数字的限定词（over/under、超过/不到、约、左右等）两边不一致不判「支持」；同一份证据里所有谈到同一件事的句子都参与比对，先支持后更正的得到「无法定论」。
- 新增回归测试：40 字节 HEIC 与 AVIF、诱饵目录项、大端序、6 MB 正常 TIFF、五种新的数字漏判。冒烟脚本也加了 40 字节 HEIC 一项。

## 6. 没有验证的事项与剩余风险

| 项 | 说明 |
|---|---|
| 生产数据库上的限额与计量 | 预览环境没有后端密钥，走的是内存回退。逻辑有测试，但「真数据库 + 真流量」没跑过。迁移应用后跑一次冒烟脚本即可确认 |
| 调用方 IP 的可信度 | 限额按 `x-forwarded-for` 第一段识别调用方。Vercel 会覆盖这个头，所以在 Vercel 上可信；换到别的平台部署时必须确认前置代理也这么做，否则限额可被伪造头绕过 |
| 分布式滥用 | 每调用方限额挡不住大量不同 IP。兜底是全站每日上限，代价是被刷满后正常用户当天也用不了 |
| 被当作抓取跳板 | 远程抓取只取回内容做核验、不把内容返回给调用方（只返回哈希和元数据），所以当不了通用代理；但可以被用来让本站向某个公网地址发请求。限额把规模压在每天 1,000 次以内 |
| C2PA 库自身的漏洞 | 原生代码解析不可信输入。已锁定版本、设超时，但库本身的内存安全依赖上游。升级该库时必须重跑「不联网」测试：设置格式一变，联网可能悄悄恢复（代码里有失败即关闭的检查，但测试是最后一道） |
| EXIF 读取器是自写的 | 好处是攻击面小、成本可预测；代价是只认标准结构，少数厂商的非标准写法可能读不到字段（会如实报告为「无元数据」，不会误判）。已与原库在真实样本上逐字段对比，结果一致 |
| 同步计算无法中断 | 解析和文本比对是同步代码，超时只能靠输入上限来保证。目前各上限下的最坏耗时都在测试里有断言（均小于 2 秒）。如果将来引入的代码出现同步死循环，HEIC 那条测试会卡住而不是优雅失败，但 CI 仍会超时报错 |
| C2PA 联网探测的覆盖面 | 远程清单、成分、证书里的各类地址、时间戳均已测过（3.6）。没测的：CAWG 身份断言的 `did:web` 解析；不经过 HTTP 客户端的网络访问（观察手段看不到） |
| 第三轮修复未经独立复审 | 严格的「支持」规则、不可见字符清洗、EXIF 扫描顺序由回归测试覆盖，但没有再交给第四轮复核 |
| ClaimCheck 的严格规则会少判「支持」 | 有意为之。真实相符但措辞或数字写法不同的，会得到「无法定论」 |
| 证书吊销 | 不检查，见 3.6 |
| 既有问题 | CSP 含 `unsafe-inline`；Supabase 三个 `SECURITY DEFINER` 视图。均非本次引入，见 `07` 技术债 |
