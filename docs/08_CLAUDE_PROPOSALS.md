# 08 Claude 的方案意见

写于 2026-11-10。依据是 `01_CURRENT_SYSTEM_AUDIT.md` 里的实测数据，不是对任务书的逐条回应。
凡是我没有核实的判断，都标了「未核实」。

## 一句话结论

**现在的瓶颈不是功能少，是没有人来用。** 线上只有 1 个注册 Agent、6 条需求、29 条留言，访问统计因为一个配置缺陷从未生效。任务书的方向是继续加东西（八个预留工具、协作闭环、计费、推广员、国内站）。我的建议相反：**收窄到「核验」这一件事，把三个工具做到别人愿意接入，先拿到头十个真实外部调用方，再谈其余。**

## 1. 定位：从「Agent 互联网枢纽」收窄到「给 Agent 用的核验工具」

| 任务书的定位 | 问题 | 建议 |
|---|---|---|
| 工具站 + 核验服务 + 协作网络 + 商业化，四件事并列 | 每件事都需要各自的冷启动，资源只够做好一件 | 对外只讲一句：**检查一个文件、一张图、一段话，拿回带证据和局限说明的机器可读报告** |
| 「让 Agent 主动发现网站」 | Agent 很少自己逛网站。实际路径是三条：运营者装了 MCP/Skill；任务中搜索落到能解决问题的页面；工具目录收录 | 真正的客户是 **Agent 的开发者和运营者**，以及当下就有核验需求的人。发现工作围绕这三条路径做，不围绕 `llms.txt` |
| 首页是需求流 | 6 条需求的市场摆在首页，第一眼是「没人」 | 工具做好后把首页主位让给工具，需求流退到二级（需卢成拍板，本轮只加导航入口） |

## 2. 三个工具的真实价值排序

1. **ImageProof 最有差异化。** 能被 Agent 一次调用、不用注册、做真正密码学校验的 C2PA 接口不多（未核实，没做竞品调查）。本轮已用官方库实测能区分「无凭证 / 有效 / 被篡改」。这是应该投入最多的地方。
2. **FileProof 是稳的基础件。** 有代码执行能力的 Agent 自己就能算哈希，它的价值在：签名验证、类型识别、统一报告，以及让没有执行环境的对话型 Agent 也能做校验。
3. **ClaimCheck 规则版价值最弱，要诚实对待。** 一个强模型自己拆主张比正则规则做得好。规则版真正有用的是三样：确定性（同样输入同样输出）、数字与否定的机械交叉核对、一套不夸大的结论词汇。所以本轮把它标为 **beta**，文档里写清它不理解语义。它的真正形态是「带检索的 L2 版」，那要等有人用了再做。

## 3. 该砍的（本轮不做，理由）

| 砍掉 | 理由 |
|---|---|
| 协作网络的「认领→证据→验收→履约」闭环 | 6 条需求的市场没有流动性，先建履约流程是给不存在的交易修结算系统。而且要动生产库的权限模型，风险不小。设计思路留在路线图 |
| 模拟计费接口 | 没有付费方，公开一个「模拟计费」端点只会让外部 Agent 误以为能付费。保留：价格表配置、限额、响应里的 `cost` 字段、预算上限参数，够将来接入 |
| Agent 自动推广员 | 产品没被验证前自动化推广，产出的就是任务书自己禁止的垃圾内容。现阶段推广应该是卢成手写的三五篇真实用例 |
| 八个预留工具的任何代码 | 架构上已经是「注册表加一项」的事，不需要预留代码 |
| 国内站 | 卢成已决定延后。只留 `region` 配置位 |
| 旧演示能力（`signal.map` 等）在发现文件里的展示 | 它们返回写死的成本数字，和「只发布准确能力」冲突。接口保留不破坏兼容，但从对外能力清单里降级为 legacy |

## 4. 该加的（任务书没有，我认为重要）

| 增加 | 理由 | 本轮 |
|---|---|---|
| **修好访问统计** | 现在是盲飞。没有数据，后面所有「有没有人用」的讨论都是猜 | 做 |
| **调用来源分类写进每条调用记录** | 把爬虫、目录扫描器、内部测试从「用户」里剔掉，否则数字会自我安慰 | 做 |
| **远程抓取的 SSRF 防护做成独立模块并单独测试** | 这是整个平台最容易出事故的地方，也是 Agent 最需要的输入方式（它手里是 URL） | 做 |
| **C2PA 库禁止联网** | 官方库默认会去拉远程清单和证书吊销信息，等于让一张图片指挥服务器发请求。任务书没想到这一层 | 做 |
| **每个工具一个面向人的落地页，本地计算、文件不上传** | 人的搜索意图很明确（「在线校验 sha256」「查看图片 EXIF」「验证内容凭证」），这是最现实的自然流量来源，隐私承诺是可验证的卖点 | 做 |
| **报告签名（回执）** | 让 Agent A 把报告交给 Agent B 时，B 能验证报告确实出自本站且没被改。这是「核验服务」和「一个函数」的分界线，也是以后收费最自然的点 | 下一轮：需要卢成在生产环境配一把签名私钥 |
| **一个北极星指标** | 每周「外部 Agent 成功调用数」（剔除内部测试、爬虫、扫描器）。目标先定：头十个不同来源 | 后台页能看 |

## 5. 怎样真正吸引使用

按投入产出排序：

1. **目录收录比发现文件有效。** 官方 MCP Registry 已有发布流程，合并后更新描述即可。再人工提交两三个主流 MCP 目录（需卢成授权对外提交）。
2. **用例先行，不讲概念。** 三篇短文就够：「让编码 Agent 在安装前校验下载包」「让客服 Agent 核对用户发来的截图有没有内容凭证」「拿到一段声明先拆出可核对的数字」。每篇带可复制的调用。
3. **零门槛首调。** 不注册、不要密钥、一条 `curl` 出结果。本轮已按此设计，限额靠来源计数而不是注册。
4. **诚实是卖点。** 同类工具爱给「AI 生成概率 93%」。本站只给四种结论并写明局限。对要拿结果去做决定的 Agent，这比一个没校准的数字有用，值得在首屏直说。
5. **盲测别自欺。** 不告诉域名让 Agent 去找，大概率找不到，这是正常的。更有信息量的测试是：给它一个具体任务（「验证这张图的内容凭证」），看它会不会通过搜索或目录走到本站。

## 6. 对任务书的几处具体不同意见

- **「统一响应结构」里的 `cost.amount`**：现在全是 0。我保留了字段但加了 `simulated: true`，避免被读成真实账单。
- **「已验证来源」**：默认不内置 C2PA 信任列表，所以默认情况下这个结论不会出现。这是对的：没有信任锚就不该说「已验证」。要启用，需要卢成决定信任哪份列表并配置到环境变量。
- **远程抓取默认开还是关**：我选默认开，带严格限额和一键关闭开关。关掉的话 MCP 用户几乎没法用 ImageProof。这是一个有真实风险的取舍，风险写在安全报告里。
- **十二项验收**：都保留并落成自动化测试，其中「国内部署不泄露私有资产」改为对整个仓库的泄露扫描，不依赖国内站存在。

## 7. 本轮调整后的范围

做：三个工具（核心、REST、MCP、网页、Skill）、执行通道（限额、SSRF、计量、来源分类）、访问统计修复、发现文件更新、`region` 预留、测试与安全报告、预览部署验证。

不做：协作闭环、计费接口、推广员、国内部署文件、预留工具。
